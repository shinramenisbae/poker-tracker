# Rake tracking — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rake stops being a fake player and becomes money: an amount and a holder per session, a ledger that says who holds what, and a #rake channel the bot keeps up to date.

**Architecture:** A ledger table is the only source of balances — every movement is a row, nothing is stored as a running total. The tracker records each session's rake and holder and writes the matching ledger row; the bot reads the ledger for `/rake` and posts each change to #rake.

**Tech Stack:** Node 22, Express 4, `sqlite3`, CommonJS backend; ESM bot on discord.js; React 19 + TypeScript frontend.

**Spec:** `docs/superpowers/specs/2026-09-18-rake-banker-merge-design.md` (Part C)

# PR 3a — rake in the tracker

### Task 1: Ledger arithmetic (`backend/rake-ledger.js`)
`balancesFrom(entries)` → `{total, holders: [{name, balance}]}`, sorted by balance desc, zero balances dropped.
`checkEntry(entry, balances)` → `{ok} | {ok: false, reason}` refusing a spend or hand-over that would take someone below zero, a non-positive amount, a hand-over to yourself, and a missing name.
Entry kinds: `session` (credit `toName`), `spend` (debit `fromName`), `give` (debit `fromName`, credit `toName`), `adjust` (credit or debit, admin).
Tests: opening balances; a session credit; a spend; a hand-over nets to zero; overspending refused with the real balance; adjust up and down; rounding to cents.

### Task 2: Storage (`backend/database.js`)
`ALTER TABLE sessions ADD COLUMN rakeAmount REAL NOT NULL DEFAULT 0`, `rakeHolder TEXT`; `CREATE TABLE rake_entries`; partial unique index on `(sessionId) WHERE kind = 'session'`.
Test: the columns and table exist, and a second `session` row for one session is rejected.

### Task 3: Rake in the session's money (`backend/rake-session.js`, used by `end-session.js`)
`rakeFromPlayers(players)` → the rake carried by a leftover `Rake`-style row: cash-out − buy-ins, plus the row ids to delete.
`endSession` gains `{rakeAmount, rakeHolder}`: convert a leftover row (typed amount wins), store amount and holder, write one `session` ledger entry crediting the resolved holder (banker when no holder is given), skip entirely at $0.
Tests: a `Rake` player converts; a typed amount wins and reports the discard; $0 writes no entry; the holder defaults to the banker; an explicit holder is kept.

### Task 4: Endpoints (`backend/server.js`)
- `GET /api/rake` → `{total, holders, entries}` (newest 100).
- `POST /api/rake/entries` → validates through `checkEntry`, writes, returns `{entry, total, holders}`; 409 on refusal.
- `PUT /api/sessions/:id/rake` → `{amount, holder}` updates the session and its ledger row (deleting it at $0), returns the session plus balances.
- `POST /api/sessions/:id/end` accepts the rake fields.
Verified by hand with curl.

### Task 5: Settlement (`app/src/utils/calculations.ts`, `bot/settlement.js`, `bot/results-message.js`)
Pot balances as buy-ins = cash-outs + rake. `SettlementSummary` gains `rake: {amount, holderName, holderIsBank}`; the rake is a bank transfer from banker to holder and counts in `bankTransfersOut`. The results message gains a `🧾 Rake $133 → Stephen` line.
Tests both sides, same fixtures.

### Task 6: The UI (`app/src/pages/SessionDetail.tsx`, `Results.tsx`, `components/SettlementView.tsx`)
End Session opens a small dialog: rake amount (default $0) and holder (default "whoever banks"). The results page shows the rake line and an Edit control for amount and holder.
Tests: ending with rake sends it; the results page shows and edits it.

### Task 7: History (`scripts/convert-rake-players.js`)
Dry run by default: each `rake`/`rale`/`stephen rake?` row becomes its session's `rakeAmount` (cash-out − buy-ins) and the row is deleted; a $0 row is just deleted; no ledger entries. `--apply` after a backup.

# PR 3b — rake in Discord

### Task 8: Channel (`bot/settings.js`, `/setup`, `/settings`)
`rakeChannelId` column on `bot_settings`, `/setup rake_channel:#rake`, shown by `/settings`, DB-over-env precedence like every other field.

### Task 9: Messages (`bot/rake-message.js`)
`formatSessionRakePost`, `formatSpendPost`, `formatGivePost`, `formatAdjustPost`, `formatBalance` — pure, tested: the per-session post, the running total, per-holder lines, and the correction line.

### Task 10: Commands (`bot/index.js`)
`/rake spend|give|balance|adjust`, permission through `/link` (holder) or Manage Server (admin), each writing through the tracker API and posting to #rake. `POST /rake-posted/:entryId` for the tracker to trigger the per-session post; the message id is stored on the entry so a correction edits it.

### Task 11: Seed and ship
Opening balances as three `adjust` entries, conversion script run after review, deploy both groups.
